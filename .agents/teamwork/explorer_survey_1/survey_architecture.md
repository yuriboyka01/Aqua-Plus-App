## 1. Executive Summary & Tech Stack Overview

AquaPlus Service OS is a production web and mobile hybrid application designed for an RO water purifier service and maintenance business in Madurai, Tamil Nadu. The project combines a modern React 19 single-page application with a Node/Express backend middleware and Capacitor 8 for Android APK distribution.

### Tech Stack Breakdown

| Layer | Technology | Version | Purpose & Notes |
|---|---|---|---|
| **Frontend Framework** | React + React DOM | `^19.0.1` | Modern React with hooks, `lazy()`, `Suspense`, no legacy class components. |
| **Bundler & Dev Server** | Vite | `^8.3.0` | Ultra-fast dev server on port 3000 (`0.0.0.0`), path alias `@` -> project root. |
| **Language & Typings** | TypeScript | `^7.0.2` (dev) / Node 22 types | Strict typing enabled in `tsconfig.json`. |
| **Styling & Design System** | Tailwind CSS v4 | `^4.3.3` via `@tailwindcss/vite` | Custom themes: Deep Bottle Green (`#0C231F`), Tactile Parchment (`#FAF8F3`), Editorial Serif (`Fraunces`), Mono (`JetBrains Mono`). |
| **Icons** | `lucide-react` | `^0.546.0` | Comprehensive icon library used universally across sidebar, navbar, mobile nav, and action badges. |

| **Mobile Shell** | Capacitor | `^8.5.3` (`@capacitor/core`, `@capacitor/android`, `@capacitor/cli`) | App ID `com.aquaplus.service`. Packages `dist/` into an Android APK with `CapacitorHttp` and OTA via `CapacitorUpdater`. |

## 3. Navigation & Routing Architecture

### Key Finding: Tab-Based Router (State-Driven SPA)
The application does **not** use `react-router` or hash-based routing. Instead, navigation is entirely state-driven using a unified `ActiveTab` type managed in `src/App.tsx` and defined in `src/components/Sidebar.tsx`.

### Navigation Definitions (`src/components/Sidebar.tsx`, lines 20–28)
```typescript
export type ActiveTab =
  | 'dashboard'
  | 'customers'
  | 'record_service'
  | 'service_history'
  | 'reminders'
  | 'daily_reports'
  | 'settings'
  | 'automated_tests';
```

### Desktop Sidebar Implementation (`src/components/Sidebar.tsx`)
- **Container**: Fixed left sidebar (`hidden md:flex`, `w-64` expanded, `w-20` collapsed), background `#0C231F`, border `#1C3E37`.
- **Primary vs. Secondary Items**:
  - `primaryItems = navItems.slice(0, 5)`: Rendered directly.
  - `secondaryItems = navItems.slice(5)`: Collapsible under a "More" toggle button (`+` / `−`), automatically expands when any secondary item is active (`secondaryActive`).
- **Active State Visuals**:
  - Background `#174238`, text `#FAF8F3`, left vertical accent bar (`bg-[#7EE787] w-1 h-5 rounded-r`), active icon highlight `#7EE787`.
- **Badges**:
  - Dynamic count badges (e.g. reminders due today + overdue, test counts `11/11`).

### Mobile Navigation Implementation (`src/components/MobileNav.tsx`)
- **Container**: Fixed bottom bar (`fixed bottom-0 inset-x-0 z-40 bg-[#0C231F] border-t border-[#1C3E37] px-2 py-2 md:hidden`).
- **Main Layout**: Uses `flex items-center justify-around`.
- **Current Items**:
  1. `Home` (`LayoutDashboard`, activeTab === 'dashboard')
  2. `Customers` (`Users`, activeTab === 'customers')
  3. **Center Floating Action Button**: `-mt-6 bg-[#C25E00] w-14 h-14 rounded-full border-2 border-[#FAF8F3]` with `Wrench` icon to trigger `onOpenRecordService()`.
  4. `Reminders` (`BellRing`, activeTab === 'reminders', red badge dot for pending items).
  5. `Settings` (`Settings`, activeTab === 'settings').

### Top Navbar (`src/components/Navbar.tsx`)
- Sticky top header (`sticky top-0 z-20 bg-[#FAF8F3]/95 backdrop-blur-md border-b border-[#E5DEC9]`).
- Includes global search input (auto-switches to `customers` tab when typing), display of current date (Kolkata time), auth status / sign-out button, and primary desktop CTA button "Record Service".

## 4. Existing View Patterns & Conventions

### Component & State Conventions
1. **Lazy Loading of Pages and Modals**:
   - In `App.tsx`, all pages and modals are loaded via `React.lazy()` with `Suspense` fallbacks. This ensures fast initial bundle loading on mobile network connections.
2. **Central Data Subscriptions in `App.tsx`**:
   - Real-time Firestore subscriptions (`subscribeCustomers`, `subscribeServiceRecords`, `subscribeReminders`, etc.) are established in a single `useEffect` hook in `App.tsx` upon successful owner authentication.
   - Child pages receive data as props and notify `App.tsx` via callbacks (e.g. `onOpenCustomerDetail`, `onRecordServiceForCustomer`).
3. **Local Filtering & Search via `useMemo`**:
   - Pages like `CustomersPage` and `RemindersQueuePage` manage local state for filters (status, locality, brand, search query) and sort order using `useMemo`.
4. **Editorial & Tactile Design Language**:
   - **Backgrounds**: Canvas parchment `#FAF8F3`, cards `#F4F0E6`, borders `#E5DEC9` and `#DDD6C5`.
   - **Accents**: Deep forest green `#0C231F`, teal `#163830`, amber `#C25E00`, mint `#7EE787`, coral `#E07A5F` / `#FF8B8B`.
   - **Typography**: `font-editorial` (`Fraunces` serif) for section headers and titles; `font-mono-data` (`JetBrains Mono`) for IDs, numbers, costs, and dates; system sans for body text.
5. **Responsive Layout Hybrid (Table on Desktop, Cards on Mobile)**:
   - Pages use `<div className="overflow-x-auto"><table ...>` with horizontal scroll support, or responsive grid cards.
   - Forms and drawers use bottom/right slide-ins (`slide-in-from-right` or bottom modal sheets) that work smoothly on both desktop monitors and 360–390px mobile screens.

## 5. Touch Points for Inventory Management Integration

To seamlessly integrate the new Inventory Management feature into AquaPlus Service OS, the following touch points must be updated:

### Touch Point 1: Navigation Type & Items (`src/components/Sidebar.tsx`)
- **Action**: Add `'inventory'` to `ActiveTab`:
  ```typescript
  export type ActiveTab =
    | 'dashboard'
    | 'customers'
    | 'inventory'          // <-- NEW
    | 'record_service'
    | 'service_history'
    | 'reminders'
    | 'daily_reports'
    | 'settings'
    | 'automated_tests';
  ```
- **Sidebar Nav Item**:
  - Add `inventory` entry to `navItems` with icon `Package` (or `Boxes`) from `lucide-react`:
    ```typescript
    {
      id: 'inventory' as ActiveTab,
      label: 'Inventory',
      sublabel: 'Parts & stock levels',
      icon: Package,
      badge: lowStockCount > 0 ? `${lowStockCount} low` : null,
      badgeColor: 'text-[#FF8B8B]',
    }
    ```
  - **Slicing Consideration**: Currently `primaryItems = navItems.slice(0, 5)`.
    - If `inventory` is placed as item 3 (after Customers), `primaryItems = navItems.slice(0, 6)` will keep Dashboard, Customers, Inventory, Record Service, Service History, and Reminders in primary view, while Daily Reports, Settings, and System Checks remain under "More".
    - Pass `lowStockCount` prop into `<Sidebar />`.

### Touch Point 2: Mobile Navigation (`src/components/MobileNav.tsx`)
- **Action**: Add `inventory` tab button to mobile bottom bar.
- **Recommended Layout**:
  - Option A (5 items with floating center):
    `Home` | `Customers` | `[Floating Wrench]` | `Inventory` | `Reminders`
    (Settings can be accessed from the Top Navbar profile icon or a secondary menu, preserving prime bottom navigation real estate for the daily field workflow).
  - Option B (6-item or sliding bar):
    Keep `Settings` and add `Inventory` with icon `Package`, compact width (`min-w-[52px]`).
  - Badge indicator: Show a small red badge dot on `Package` if `lowStockCount > 0`.

### Touch Point 3: Application Coordinator (`src/App.tsx`)
- **Lazy Page Import**:
  ```typescript
  const InventoryPage = lazy(() => import('./pages/InventoryPage').then((m) => ({ default: m.InventoryPage })));
  ```
- **State Management**:
  ```typescript
  const [inventoryItems, setInventoryItems] = useState<InventoryItem[]>([]);
  ```
  - Real-time subscription in `useEffect`:
    ```typescript
    const unsubInventory = subscribeInventoryItems(effectiveOwnerId, setInventoryItems);
    ```
- **Low Stock Computation**:
  ```typescript
  const lowStockCount = inventoryItems.filter(item => item.quantity <= item.minStockThreshold).length;
  ```
- **Conditional Page Render**:
  ```tsx
  {activeTab === 'inventory' && (
    <InventoryPage
      inventoryItems={inventoryItems}
      onAddItem={handleCreateInventoryItem}
      onUpdateItem={handleUpdateInventoryItem}
      onAdjustStock={handleAdjustInventoryStock}
      onDeleteItem={handleDeleteInventoryItem}
    />
  )}
  ```

### Touch Point 4: Domain Models & Types (`src/types/index.ts`)
- Add definitions for `InventoryItem`, `InventoryCategory`, `StockAdjustment`:
  ```typescript
  export type InventoryCategory =
    | 'Spun Filter'
    | 'RO Membrane'

    | 'Sediment Filter'

  export interface InventoryItem {
    id: string;

    supplier?: string;
  ```

### Touch Point 5: Firestore Database & Security Rules (`dbService.ts` & `firestore.rules`)
- **In `src/services/dbService.ts`**:
  - `subscribeInventoryItems(ownerId, callback)`
  - `addInventoryItem(data, ownerId)`
  - `updateInventoryItem(id, data, ownerId)`
  - `adjustInventoryStock(id, newQuantity, reason, ownerId)`
  - `deleteInventoryItem(id, ownerId)`
- **In `firestore.rules`**:
  - Define `isValidInventoryItem(data)`.
  - Add `match /inventoryItems/{itemId}` rule with owner authorization and strict field validation (`data.keys().hasOnly(...)`).

### Touch Point 6: Gemini Vision AI Image Scanning Backend Route (`src/server/apiMiddleware.ts` & `src/services/apiService.ts`)
- **Backend API Endpoint**: `POST /api/inventory/scan`
  - Ingests image payload (base64 or multipart).
  - Uses `@google/genai` (already in `package.json`) with `process.env.GEMINI_API_KEY`.
  - Prompts Gemini Vision model to extract structured JSON containing:
    - Array of items: `name`, `category` (mapped to nearest AquaPlus category), `quantity`, `unitCost` / price.
    - Document type: `supplier_bill` vs `physical_parts`.
    - Confidence score and any notes.
  - Server-side invocation protects the `GEMINI_API_KEY` from client exposure (conforming to Project Rule 5).
- **Client Service Function in `src/services/apiService.ts`**:
  - `scanInventoryImage(file: File | string): Promise<ScannedInventoryResult>`
  - Handles authorization header (`Authorization: Bearer ${token}`) and resolves URL using `resolveApiUrl()`.

### Touch Point 7: Linking Parts Usage with Service Records (`RecordServiceModal.tsx`)
- Currently in `RecordServiceModal.tsx`, replaced parts are tracked as freeform text `filtersReplaced: string` and a manual `partsCharge: number`.
- The new inventory model can be seamlessly surfaced in `RecordServiceModal.tsx` as a smart parts selector:
  - Select items from `inventoryItems` (e.g. "Spun Filter", "RO Membrane 75 GPD").
  - Auto-populates `partsCharge` based on item price.
  - Deducts stock upon recording completed service visit.
